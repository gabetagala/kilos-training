# Wedding Directory (working name)

Personal project idea, spiked 2026-08-17. **Not part of Kilos.**

Free PH wedding-planning app for couples (requirements checklist + payments
tracker), monetized on the supplier side via a claim-your-listing directory.
Differentiator: **price transparency** — every venue page shows a starting
rate (published or couple-submitted), attacking "PM sent po" culture. The
Glassdoor dynamic: vendors claim their page to control the number.

## Seed data (`seed-data/`)

First scrape of PUBLIC venue info — 4 research agents over public web only
(venue sites, rate blogs, news features). No photos, no personal numbers,
sources cited per row.

- `seed-venues.json` / `seed-venues.csv` — 72 unique venues after dedupe
  (Tagaytay 16, Metro Manila 15, beach/destination 15, cross-region blog
  sweep 26)

**Headline stats (2026-08-17):**

- 58/72 (81%) have a price signal findable somewhere public
- 56 have an actual PHP figure; only ~36 are fresh (2024–2026) — the rest are
  2014–2022 vintage. Stale prices are the claim-your-listing sales hook.
- Confirmed quote-on-inquiry-only ("PM sent po" tier): Manila Hotel, Okada,
  EDSA Shangri-La, Marriott, Club Punta Fuego, Acuatico, Bluewater Maribago,
  Kahuna, Twin Lakes, Farm Hills, Aquila, Escala, Gazebo Royale, La Bella.
- Two venues found permanently closed and excluded: Sofitel (Jul 2024),
  Hanging Gardens QC (Aug 2024).

## The app (`app/`)

Vanilla JS + CSS, no build step. Serve it and open:

```bash
cd app && python3 -m http.server 4173     # → http://localhost:4173
```

- `index.html` / `style.css` / `app.js` — the whole app
- `data.js` — generated by `scripts/gen-app-data.mjs` (never hand-edit)
- `photos/` — one Google Places photo per venue, attribution in
  `seed-data/photo-map.json` and rendered on every image
- `_frame.html` — dev harness: seeds a demo plan and renders the app in a
  sized iframe (`?w=390&h=1400&tab=venues&venue=Hillcreek`) for screenshots
  at phone/tablet/laptop widths

Three surfaces: **Plan** (categories, per-item payment schedules, "Next up",
budget meter, guest count), **Venues** (photo cards, filters, detail panel),
**Ask** (computed answers over the dataset + the couple's own plan).

State is localStorage only (`wd-profile`, `wd-plan`). Partner sync and a real
LLM behind Ask both need a backend — the UI says so rather than faking either.

### Photo rules

Photos are fetched per venue from Google Places (`scripts/fetch-photos.mjs`,
then `rescue-photos.mjs` for stricter name matching). Matching is deliberately
strict — every significant word of the venue name must appear in the candidate,
≥2 words, and the address must corroborate. A loose matcher put Shangri-La's
pavilion on Crimson Mactan and Hillcreek's garden on two other venues; a wrong
photo is worse than no photo, so 24 venues ship photo-less by design.

## Data caveats

- `starting_rate_php` mixes rate types: venue-only vs all-in package vs
  per-head (Radisson Blu Cebu = ₱2,500/head!) vs minimum spend. Add
  `rate_type` + `rate_basis` (nett vs +++) before comparing anything.
- Every row's `rate_notes` says what the number covers and its source year.
  Rows flagged "dated" need re-verification before publishing.

## Rules already decided

- Couples side: free forever. Price display mandatory and never paywalled.
- Vendor claiming + corrections: free. Paid = leads, featured placement
  (labeled), analytics. Never secret pay-to-rank.
- Scrape facts only: no photos (copyright), no personal cell numbers (DPA).
- This is a personal project — no Spiralytics accounts/tools ever.
